### 4.2 模块职责

| 模块 | 职责 | 关键约束 |
| --- | --- | --- |
| BrowserHost | 承载页面、管理 CDP 会话、转发注入脚本 | 不阻塞主线程；会话崩溃可重建 |
| RuleEngine | 纯函数式匹配 + 动作决策，输出“处置指令” | 单请求匹配 < 5ms；规则变更热生效 |
| RequestRouter | 执行处置指令（continue/rewrite/fulfill/fail/delay） | 与浏览器实现解耦，便于换方案 |
| CaptureService | 收敛 CDP 事件为统一事件模型，写入会话总线 | 可开关、可采样；大 body 不阻塞 |
| LogCollector | 增量读取、轮转、解析、建立时间/键索引 | 大文件不 OOM；10MB/s 级吞吐 |
| CodeIndexer | 文件树、搜索、符号、堆栈映射 | 增量索引；尊重 .gitignore |
| DiagnoseOrchestrator | 上下文打包、工具调用循环、结果结构化 | 发送前可预览；工具步数上限 |
| Storage | 工作区/规则/会话/事件持久化 | 单机文件化（DEMO 无数据库）；SQLite 仅为早期草案 |

### 4.3 关键数据流

> 以下为设计意图。DEMO 的实际实现是 **webRequest 三钩子按前缀改道 / 复用 dev server 代理**，
> 不经过 CDP `Fetch` 暂停与重放，详见 [08 §8.4](./08-DEMO实现现状.md)。

**流程一：请求被路由到本地后端**

```
页面发起 XHR
  → CDP Fetch.requestPaused(requestId, request)
  → RuleEngine.match(request) → {action: forward(target: 127.0.0.1:8080)}
  → RequestRouter: Fetch.continueRequest(requestId, url 改写 / header 注入)
  → 本地后端响应 → （如需改包）Fetch.requestPaused(response 阶段）
  → 放行 → 页面收到响应
  → CaptureService 记录（含命中的 ruleId、traceId）
```

**流程二：错误捕获与聚合**

```
页面报错（4xx/5xx / 网络错误 / console.error / uncaught）
  → CaptureService 生成 ErrorEvent
  → 关联同一 traceId / 同一时间窗内的请求
  → UI 时间线标记 + 提示“检测到 N 个异常”
```

**流程三：一次诊断**

```
用户描述问题 → 点击诊断
  → Orchestrator 取上下文：命中的请求、错误事件、日志窗口(±N 秒或 traceId)、堆栈映射源码
  → 组装 Prompt（系统约束 + 证据包）
  → LLM 工具循环（最多 K 步）：search_code / read_file / query_logs / inspect_request
  → 输出结构化结论（JSON）→ UI 渲染证据链与修复建议
  → 用户采纳/追问/反馈 → 会话落库
```

> **DEMO 实现**：上述编排在三种入口（CLI / WebUI / Desktop）间共用；实际顺序为
> 预检 → 驱动 fire 取请求/响应/时刻/标记 → 等日志落盘 → 组 prompt → agent 循环（轮次上限可配置，留空不限）
> → DiagnosisResult → 脱敏报告。模型侧通过 Claude Agent SDK 拉起 Claude Code 子进程；认证优先使用模型设置中的应用凭据（safeStorage 加密 Token 或指定环境变量），未配置时加载用户 Claude Code 设置；
> 工具由 **进程内 MCP**（日志、数据库、证据切片、沙箱 run_command）和 **内置 Read/Grep/Glob**（仅授权源码根、路径白名单、敏感文件拒绝）共同提供；工具模式分「只读 / 沙箱 / 完全权限」：沙箱与完全权限模式在 Git 项目中复用同一套原地会话（首次写入前保存内容快照、baseline/journal、仓库锁、保留/丢弃与崩溃恢复），完全权限即使未显式请求沙箱也会强制走该会话；非 Git 项目使用隔离副本；完全权限仅额外开放 Bash。仓库锁被占用时自动降级只读，并在结果中记录占用诊断的 runId/pid/时间，实时结果提供锁释放后的重试入口。沙箱修改对当前状态执行编译自测后不自动回滚，由用户点击「保留修改 / 丢弃修改」决定；写入过程持续落盘 `workspace-journal.json`，应用重启后扫描未收尾会话并逐条提示保留/丢弃，外部修改冲突不覆盖；关闭窗口、退出应用或收到 SIGINT/SIGTERM 等无确认退出场景默认保留未收尾修改并明确提示，保留失败时取消退出；删除历史诊断时若存在未收尾修改，二次确认后先 keep（释放仓库锁、清理 baseline/journal）再删除 run 目录，避免留下孤儿锁；启动时不再拷贝全部脏文件；每个实际写入文件按版本保存 pre-run 与每次写入后的快照，支持把单个文件回退到指定版本，版本备份在保留/丢弃完成后清理。非 Git 副本在复制前先统计文件数与总体积，超限时直接退回只读并说明上限；隔离副本的编译/测试在沙箱内完成，只读模式只做静态检查，不再对真实工程 apply/revert。写入保护按相对可写根判断；Git 仓库中构建产物（`target` / `dist` / `build` / `out` / `bin` / `obj` / `__pycache__` / `.gradle` / `.cache` 等）以 `.gitignore` 状态为准（仅被忽略的目录拒绝写入，已跟踪的 `build` 等源码目录仍可写），避免工程路径或沙箱路径中的 `runs` / `build` 等名称造成误拒。工具结果、内置工具输出、证据包与追问快照统一脱敏，避免密钥进入模型上下文。写入真实工作区的模式（原地、完全权限诊断、完全权限继续诊断）在收尾时若识别到可用编译/测试命令就强制运行一次，失败注入 `gates` 并标记「验证失败」；没有写入或没有识别到命令时明确记录 `skipped` 及原因。完全权限模式由用户手动开启，复用原地会话的 baseline/journal 与保留/丢弃流程；Edit/Write 不再逐次确认，Bash 中构建/测试工具链（mvn/npm/pytest 等）直接执行，其他命令额外确认（非交互环境直接拒绝），同时仍受可写路径、敏感文件和构建产物保护；其他后端源码根默认只读，Agent 对其修改只以修复建议返回，生成预览后由用户确认应用；非确定性由 **硬闸门 + n=3 多次判定** 兜底，
> 界面记录「一致 / 不一致 / 判不了」并声明“一致不等于正确”。详见 [08 §8.7 / §8.9](./08-DEMO实现现状.md)。
>
> **元素视野诊断**：桌面版通过 CDP `Overlay` 选择页面元素，提取选择器、文本、属性、关键样式、祖先链和框架组件信息（Vue/React 等），在元素旁注入 Shadow DOM 浮层收集问题，然后以 `driver=element` 走同一套 Agent/沙箱/修复/自测流程；组件文件优先来自框架开发态元数据，缺失时回退到路由、文本、属性和 class 搜索；同时从组件 import 的 API 模块提取 URL，并搜索后端 Controller/Mapper 候选；选中元素会保存区域截图到 `runs/<runId>/evidence/element.png`；Shadow DOM 选择器和同源 iframe 偏移已做基础支持。

### 4.4 内嵌浏览器与拦截方案选型

| 方案 | 请求/响应拦截能力 | 实现成本 | 主要风险 |
| --- | --- | --- | --- |
| **Electron WebContentsView + webContents.debugger（CDP）** | 强：Fetch 域可暂停/改写请求与响应，Network 域可拿全量元数据 | 中 | CDP 会话生命周期管理；body 获取需额外调用 |
| 独立本地代理（mitmproxy 类） | 强：对任意客户端生效 | 中高 | HTTPS 需证书信任；跨域/Cookie 域处理 |
| 浏览器扩展（declarativeNetRequest） | 中：声明式重定向，拿不到完整响应体 | 低 | 需安装扩展；能力受限 |
| 外置 Chrome + CDP 连接 | 强 | 低 | 非内嵌，体验割裂 |

**已确认（DEMO）**：桌面形态使用 **Electron + WebContentsView + CDP 捕获请求**；
路由控制不走 CDP 暂停改写，而是 **Electron `session.webRequest` 三条钩子按前缀改道**：

| 钩子 | 挂载 Origin | 职责 |
| --- | --- | --- |
| `onBeforeRequest` | 宿主 origin | 改写目标路由，走本地端口 |
| `onBeforeSendHeaders` | 本地 origin | 抓预检（OPTIONS）携带的头 |
| `onHeadersReceived` | 本机 origin | 补 CORS 响应头 |

“自建壳 + dev server 代理”为备用方案，可能被淘汰；CLI / Web 形态没有内嵌浏览器，
browser 场景改用 playwright-core + 无头 Edge。详见 [08 §8.3 ~ §8.6](./08-DEMO实现现状.md)。

> 设计要点：CDP Fetch.continueRequest 做 URL 改写时，页面感知的 Origin 不变，可规避 CORS 问题；但 Set-Cookie 的 Domain 可能与本地后端不一致，需要单独的 Cookie 策略（P1 阶段处理）。

### 4.5 规则引擎设计（草案）

```json
{
  "id": "rule-001",
  "name": "订单接口走本地",
  "enabled": true,
  "priority": 100,
  "match": {
    "methods": ["POST", "PUT"],
    "urlPattern": "https://api.example.com/api/order/**",
    "resourceTypes": ["xhr", "fetch"],
    "headerConditions": [{ "name": "x-env", "op": "eq", "value": "prod" }]
  },
  "action": {
    "type": "forward",
    "target": "http://127.0.0.1:8080",
    "pathRewrite": { "from": "^/api/order", "to": "/order" },
    "headers": { "set": { "X-DebugCopilot": "1" }, "remove": ["Cookie"] },
    "timeoutMs": 30000
  },
  "injectTraceHeader": true
}
```

- **动作类型**：forward（转发）、mock（本地响应）、abort（中断）、delay（延迟）、patch（改包：JSONPath 或脚本表达式）。
- **匹配优先级**：priority 降序 → 同优先级按创建时间 → 首个命中生效（first-match wins）；命中后在 UI 中明确展示“被哪条规则处理”。
- **冲突与调试**：规则变更热生效；提供“为什么没命中”的诊断（逐条件求值结果）。
- **trace 关联**：命中请求可注入 X-DebugCopilot-Trace-Id（或复用后端已有的 trace header 名），用于日志关联。

> 规则 DSL 的完整字段、脚本沙箱能力与匹配语义详见后续同步（§11 T2）。

### 4.6 日志采集设计（草案）

- **增量读**：记录 fileId + offset，定时轮询文件大小；检测截断/轮转后重置偏移。
- **多行合并**：以“新行是否匹配起始模式（时间戳/级别）”为界，将堆栈行归并到上一条。
- **解析产物**：{ ts, level, logger, thread, traceId, message, stack, raw }。
- **索引**：按时间排序的环形缓冲 + 关键字倒排（内存）；超出阈值的大文件外置到磁盘。
- **查询语义**：timeWindow、keyword、traceId、level >= WARN，返回行号与上下文行。
- **关联策略（三层）**：① 参数 marker（仅 CLI/scenario fire 模式，capture 结构上不注入）；② 时间窗 + 线程；③ 业务 ID（跨线程）。traceId 仅在目标确实写入时作为补充，**不作为主路径**；结论中标注实际关联方式与可信度。capture 落到 `time-window` 时明确标注“兜底，可能混入其他请求”。

> **DEMO 实现**：不使用 traceId，而是在请求 body 的“可回显、不参与业务”字段注入 `dcprobe<随机hex>`，
> agent 用 `get_logs({marker})` 子串匹配日志；无安全字段时不注入并在 prompt 中声明。
> 落盘等待为固定 sleep 1.2s（实测延迟约 150ms）。
> 日志读取为**纯读文件 + 流式 readline + iconv-lite(GBK)**，识别轮转与堆栈续行，解析用预设/regex，
> 自动探测要求 >60% 命中且全可解析；**每次调用全量线性扫，不建索引**。
> 该策略在 M1/M2 扩展为三层（marker / 时间窗+线程 / 业务 ID），详见 [08 §8.8 / §8.9](./08-DEMO实现现状.md)。

### 4.7 源码索引与堆栈映射（草案）

- **索引**：文件树 + ripgrep 搜索；tree-sitter 解析符号大纲（按语言逐步接入）。
- **堆栈映射启发式**：

| 语言 | 堆栈形态 | 映射规则 |
| --- | --- | --- |
| Java | com.foo.Bar.baz(Bar.java:42) | 包路径 → 目录，类名 → 文件名，行号直取 |
| Node | at fn (/abs/path/file.js:10:5) | 绝对路径直接命中；node_modules 降权 |
| Python | File "/abs/path/x.py", line 10 | 路径直接命中 |
| Go | main.handler(0x...) /path/x.go:42 +0x1a | 取 file:line |

- **脱敏**：发送源码片段前，按规则扫描并去除密钥类字符串。

### 4.8 诊断编排（草案）

**上下文包（Evidence Pack）**

```
symptom   : 用户描述、页面 URL、发生时间
http      : 相关请求/响应摘要（错误优先，含命中规则）
errors    : console error / uncaught 异常堆栈
logs      : 时间窗或 traceId 命中的日志片段（含关联方式说明）
code      : 堆栈帧映射到的源码片段（file:line + 前后文）
workspace : 技术栈、目录约定、可用工具说明
```

**工具集（LLM 可调用）**

| 工具 | 说明 | 限额 |
| --- | --- | --- |
| query_logs(timeWindow, keyword?, traceId?) | 检索日志 | 每次返回行数上限 |
| inspect_request(id) | 查看某个请求的完整信息 | — |
| search_code(pattern, glob?) | 全文搜索 | 结果数上限 |
| read_file(path, range) | 读取源码 | 单次字节上限 |
| git_log(path, limit) | 最近改动线索 | P2 |

> 参数化运行时事实（2026-11-18）：新增 `runtime_facts`，按 `pid/port + view + selectors` 读取 `system_properties`、`classloader`（VM.classloader_stats）、`flags`、`command_line`；selectors 只支持精确/前缀/简单通配，敏感键值永远脱敏，通配仅返回键名。支持 `comparePid` 或 `declaredFile` 只返回 `missing-in-a/missing-in-b/different` 差异；无 selector 只返回键数/分组/样例键。结果复用分页/溢写/query_result。classloader 不返回 jar URL，env/open files 留 P1。
>
> 构建模型探针（2026-11-18）：新增 `buildProbeRoot`（留空默认 `dirname(sourceRoot)`）；`inspect_build_model` 在只读白名单内解析源码根/父级 `pom.xml` 的 modules、parent、坐标，以及 `.idea/modules.xml` / `.iml` 的 sourceFolder/output，输出时间戳与 staleHints（IDE 早于 POM、模块不一致、路径缺失）。探针根只服务该工具，不开放通用源码读取；拒绝 `.idea/workspace.xml`、同级其他源码和敏感文件。P0 不执行 `mvn help:effective-pom`。
>
> 长列表分页（2026-11-17）：列表工具发生截断时先把全量 redacted JSON 写入 run/evidence，返回 `totalCount/offset/limit/nextOffset/truncated/file/fields` 与下一页数据；`query_result({file,field,offset,limit,filter})` 从 evidence 读取 JSON 数组并分页/子串过滤。`runtime_classpath` 不再在 diff 内部截断，工具返回各分类 counts + 第一页，支持 `mode/offset/limit`；`maven_dependencies` 不再先 slice(200)，全量过滤结果溢写并支持 `offset/limit`。`spill` 支持 force，确保即使未超过字节阈值也能为分页保存快照。
>
> 非代码修复动作（2026-11-17）：`fixes` 只承载代码 search/replace；配置、构建刷新、补打包依赖、重启/换运行实例、数据与部署环境修复写入平级的 `actions[]`。每个 action 包含 type、summary、reason、requires、steps、commands、verification、risk、reversible；P0 仅在报告/UI/CLI 展示和复制命令，不自动执行。`gates.remediation` 记录 fixes/actions 数量；fixes 为空但 actions 非空时报告明确“不需要修改代码”。Prompt 要求模型不要把非代码动作塞进 conclusion/needsMoreInfo，能在仓库内用补丁解决的仍用 fixes。
>
