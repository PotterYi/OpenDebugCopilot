## 9.1 目标与范围

**目标**：打通一条可自动化验证的 CLI 闭环。

```
场景文件 → 驱动执行 → marker 注入 → 等日志 → 证据工具 → 诊断 → 硬闸门 → DiagnosisResult → 脱敏报告
```

**包含**

| 能力 | 说明 |
| --- | --- |
| 场景解析 | browser 块 / HTTP 声明二选一，歧义直接报错；支持 `logfiles`、`source`、`marker`、`window` |
| 驱动 | browser（playwright-core + 无头 Edge）、http 两种 |
| 日志底座 | **纯读 `logfiles` 声明的文件**，不碰目标进程；流式 readline + iconv-lite（GBK）；识别轮转；堆栈续行聚合；预设/regex 解析；自动探测（命中 >60% 且全部可解析）；**每次调用全量线性扫** |
| marker | 注入、披露、日志子串匹配；无安全字段时不注入并声明 |
| 工具 | get_logs、list_threads、search_log、read_source、search_source、内置 read |
| 诊断 | Diagnoser 抽象；Mock（离线可测）与 Claude Agent SDK 两种实现；轮次软上限 24 |
| 闸门 | 硬闸门 + 可选 n 次复核（默认 1，`--recheck` 开启） |
| 持久化 | **无数据库**：配置 `configs/*.json`，诊断历史 `runs/<runId>/` |
| 产物 | DiagnosisResult（JSON）+ 白名单投影的脱敏报告（Markdown） |

**不包含（后置）**

- Electron 桌面版、WebContentsView、webRequest 三钩子、路由改道
- WebUI（`src/ui/`，M1 只留目录占位）
- 数据库（明确不做；后续如需要再评估）
- 真实 MCP 传输层（M1 用进程内函数 + MCP 形态适配）
- 自建壳 + dev server 代理（已决定淘汰）

## 9.4 关键接口（拟）

### 场景文件

```json
{
  "name": "order-create",
  "baseUrl": "http://localhost:5173",
  "browser": {
    "path": "/order/create",
    "match": "/api/order",
    "actions": [
      { "click": "#submit" },
      { "fill": { "selector": "#qty", "value": "2" } }
    ]
  },
  "logfiles": ["logs/app.log"],
  "logEncoding": "auto",
  "source": { "root": "../" },
  "parser": { "preset": "auto" },
  "marker": { "mode": "body", "bodyField": "traceNo", "header": "X-DC-Probe" },
  "window": { "beforeMs": 3000, "afterMs": 2000 }
}
```

- `browser` 与 `method`/`path` 互斥，同时出现 → 报错退出（非零退出码）。
- `parser`：`preset`（json-lines / logback / node / auto）或 `{ "regex": "..." }`。
- `marker.mode`：`body`（默认）/ `header` / `both` / `none`。

### 日志底座

```js
// evidence/logs.mjs
readLogs({ logfiles, parser, window, marker?, level?, thread? }) // 流式线性扫，返回匹配行
listThreads({ logfiles, parser, window })                        // 单次扫描的线程直方图
searchAll({ logfiles, parser, keyword })                         // 全库关键词，忽略时间窗
```

- 每次调用**重新全量扫描**，不维护索引与 offset（与 DEMO 一致，保证新鲜度）。
- 轮转：同目录下匹配 `app.log`、`app.log.1`、`app.log.*` 等，按文件名与 mtime 合并排序。

### 驱动

```js
// driver/index.mjs
selectDriver(scenario) // -> driver；歧义抛错
// 契约
fire(scenario, ctx) -> { request, response, firedAt, marker }
```

### 工具

```js
// tools/index.mjs
createTools({ evidence }) // -> { get_logs, list_threads, search_log, read_source, search_source, read }
```

对 agent 暴露 snake_case 名称 + JSON Schema；内部为普通函数，便于单测与后续接 MCP。

### 诊断与结果

```js
diagnose({ scenario, driver, tools, agent, gates, recheck }) // -> DiagnosisResult
```

DiagnosisResult 六段与 08 §8.7 一致；报告按白名单投影，投影前不得拼接原文。

## 9.5 关键设计决策（含复审修正）

| 决策 | 选择 | 理由 |
| --- | --- | --- |
| 日志采集 | 纯读文件 + readline + iconv-lite(GBK)，每次全量线性扫 | 与 DEMO 一致；不侵入目标进程；实现简单、结果新鲜；规模问题后置 |
| 日志解析 | 预设 + regex；自动探测判据：>60% 行命中且全部可解析 | 避免“半解析”导致证据错位；探测失败直接报错，不猜 |
| marker 注入 | **默认 body 安全字段**，header 可选；支持 body / header / both / none；body 必须是 JSON 对象，否则降级并记录原因 | 修正早前“header 优先”：marker 必须能被日志回显；无法注入时由 prompt 披露（S4） |
| 日志关联 | **三层**：marker → 时间窗+线程 → 业务 ID；traceId 仅目标确实写入时可用 | 单一 marker 覆盖不了跨线程场景；traceId 不能假设后端一定提供 |
| 等日志落盘 | 轮询 marker 命中，**2s 超时兜底** | 比固定 1.2s 更稳；超时降级并在报告标注 |
| agent 轮次 | 证据无增量即停，24 轮兜底 | 控成本，避免机械跑满 |
| n 次复核 | 默认 1，`--recheck N` 显式开启 | 3 次全跑成本高，复核应为显式动作 |
| 持久化 | 无数据库；`configs/*.json` + `runs/<runId>/` | 与已确认方案一致；UI 状态用 localStorage |
| 模块划分 | 沿用十模块（core/evidence/tools/agent/driver/diagnose/doctor/report/ui/app） | 边界清晰，便于三形态复用 |
| 构建 | 纯 ESM，无构建步骤 | 降低复杂度；WebUI 亦不引入框架/构建 |
| UI 栈（后置） | **零框架 HTML+JS**；Node http server + `/api/*`；桌面 Electron 45 加载同一页面 + 5 个 `dc:*` IPC | 采纳：与 CLI-first 一致；避免框架与构建成本；M1 不实现 |
| 脱敏 | 白名单投影后再渲染 | 与 DEMO 一致，默认安全 |

## 9.7 验证方式

1. **单元测试**：`node --test verify/unit`，不依赖网络与浏览器。
2. **端到端（离线）**：本地 stub HTTP 服务 + fixture 日志 + MockDiagnoser，验证场景到报告全链路。
3. **浏览器用例**：依赖本机 Edge（已确认安装），CI 缺失时 skip。
4. **真实诊断**：S5 后手动跑一次最小调用，验证网关与 SDK 可用；不纳入 CI。
5. **产物检查**：报告不得出现绝对路径、请求头值、日志/源码原文。

## 9.8 风险与应对

| 风险 | 应对 |
| --- | --- |
| 全量线性扫在大日志上变慢 | 流式读取 + 时间窗早停 + 单文件字节上限（可配），超限提示 |
| GBK/混合编码乱码 | iconv-lite 按场景配置解码；探测到解码失败时报告明确错误 |
| 日志格式未知（T3） | 三种预设 + regex 兜底；自动探测失败直接报错并提示配置 parser |
| SDK 包名/网关模型不确定 | 适配层隔离；Mock 保证主流程可测；真实调用前置检查 |
| playwright-core 依赖浏览器 | 使用系统 Edge；CI 跳过浏览器用例 |
| marker 注入改变业务语义 | 仅注入显式配置的安全字段；无安全字段则不注入并披露 |
| 无 DEMO 代码，文档与实现可能漂移 | 小步验证；发现偏差立即回写 08 并重审 09 |
