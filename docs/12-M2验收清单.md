## 12.2 手工验收（必须真实鼠标）

启动：

```bash
npm run manual:e2e
# 或保留产物：node verify/manual/e2e-harness.mjs --keep
```

步骤与**正向判据**：

| # | 操作 | 通过标准（正向断言） |
| --- | --- | --- |
| 1 | 窗口打开，观察“浏览器”页 | 能看到 Manual E2E Frontend 页面；左侧配置区、顶部 Tab 未被原生视图遮挡 |
| 2 | 用真实鼠标点击“创建订单” | 页面出现 `HTTP 500` 与后端错误 JSON（页面从 A 域请求 B 域，跨源绝对地址；预检由内置代理应答） |
| 3 | 切到“请求”Tab，点选请求 | 出现 POST /api/order，状态 500，URL 指向后端端口；详情能看到响应体（失败时可点“重新获取”） |
| 4 | 选中请求 → 诊断（Mock） | 出现 Run ID、`Gates: ok`、结论与报告；关联方式为 `business-id` 或 `time-window` |
| 5 | 切到“历史” | 新增一条记录，点击可打开 report.md |
| 6 | 拖动左右分栏分隔条，重启应用 | 左栏宽度改变；重启后宽度保持（localStorage 同 origin） |
| 7 | 修改工作区并保存，重启应用 | 配置保留；页面显示配置目录，`configs/workspace.json` 存在 |
| 8 | 修改路由并保存，触发页面请求 | 路由页显示「已加载 N 条规则」与命中次数；未命中时显示最近未命中的 URL |
| 8.1 | 点“从捕获请求生成”/请求详情“生成路由规则” | 自动生成 host+前缀候选；可改 local/SIT；“探测”显示可达/不可达 |
| 8.2 | 页面抛错后诊断 | 诊断卡片显示“前端错误 N 条 / 前端源码 M 处”；报告同步展示 |
| 9 | 反复切换 Tab、调整窗口大小 | 原生视图边界跟随内容区，不覆盖 Tab/左栏；无残影 |
| 10 | 关闭窗口 | 进程退出；临时目录清理（未加 `--keep` 时） |

> **harness 与真实使用**：`npm run manual:e2e` 使用临时配置目录（UI 会红色标注），关闭后清理，**不要用它验证配置持久化**；
> 真实使用请 `npm run desktop`，配置写入项目 `configs/`。

> 若点击无反应：先看终端里的 `[browser console]` / `[browser request failed]` 日志（stderr）。
> 验收问题追溯：工作区页显示日志文件路径（桌面版可点「打开日志」）；每次诊断在 `runs/<runId>/run.log` 记录关联策略、agent、gates 与耗时。
> harness 页面已抽成共享模块：单元测试会**实际执行 click 处理器**（假 DOM + 假 fetch），Electron 冒烟用同一份页面真实点击。

**导航状态判据**：地址栏与“已加载”状态以 `webContents.isLoading()` 为准；若打开页面后仍显示上一页 URL，按缺陷记录。

**为什么必须真实鼠标**：CDP/合成事件绕过浏览器命中测试，无法验证原生 `WebContentsView` 是否截走点击；涉及视图边界、覆盖关系与真实交互的验收不能自动化替代。

## 12.3 已知限制（验收时确认是否符合预期）

1. **跨域 + 改道**：local 规则已改由内置反向代理转发（预检由代理 204 应答，真实后端无需支持 OPTIONS）；SIT 目标仍是直连改道。
2. **预检缓存**：已加 `Access-Control-Max-Age: 0` 并在保存规则时清缓存；若发现“改规则后仍绿”，先清缓存再复测。
3. **预检**：local 规则由代理返回 204；直连/SIT 非 2xx 时把状态行改写为 `HTTP/1.1 200 OK` 并补 CORS，UI 显示“预检已兜底（原 404）”。
4. **Origin**：CORS 回显请求实际携带的 Origin（可能是 `null`），不是页面 origin；SIT 响应同样补头。验收必须用跨源绝对地址，同源形状无法验证。
4. **打包**：尚未引入 electron-builder（T24）；当前通过 `npm run desktop` 运行。
