## 3. 功能需求

优先级：**P0** = MVP 必须；**P1** = 首个可用版本；**P2** = 增强。

### 3.1 工作区管理（Workspace）

| ID | 需求 | 优先级 |
| --- | --- | --- |
| FR-01 | 新建/编辑/删除工作区；保存前端地址端口、后端地址端口、日志路径（支持多个文件/目录）、源码根目录 | P0 |
| FR-02 | 连通性与路径校验（端口是否可达、路径是否存在、日志是否可读） | P0 |
| FR-03 | 多工作区切换、配置导入导出（JSON） | P1 |
| FR-04 | 可选：启动命令/环境变量、后端进程关联（用于后续进程级诊断） | P2 |

### 3.2 内嵌浏览器

| ID | 需求 | 优先级 |
| --- | --- | --- |
| FR-10 | 内嵌浏览器加载本地/远端页面，支持多标签、前进后退、刷新 | P0 |
| FR-11 | 内置 DevTools 开关；自定义 UA、窗口尺寸、缓存清理 | P1 |
| FR-12 | 支持自签名证书/HTTPS 提示与信任策略 | P1 |
| FR-13 | 页面注入标识（如 trace header / 页面角标），提示“当前已接管” | P1 |

### 3.3 路由控制 / 流量规则（核心能力）

| ID | 需求 | 优先级 |
| --- | --- | --- |
| FR-20 | 规则匹配：HTTP 方法、URL（通配符/正则）、资源类型（xhr/fetch/document/ws）、Origin/Referer、Header 条件 | P0 |
| FR-21 | 规则动作：转发到指定上游（本地后端）、直接响应（Mock）、中断（Abort）、延迟、改写路径、增删改 Header、改写 Request/Response Body | P0（转发/中断）/ P1（Mock、改包、延迟） |
| FR-22 | 规则优先级、启停、启用状态可视化、命中次数与最近命中时间 | P0 |
| FR-23 | 规则命中日志与可回放（查看该请求的最终去向） | P1 |
| FR-24 | 规则导入导出、按工作区隔离 | P1 |
| FR-25 | WebSocket / SSE 透传与规则支持 | P2 |

### 3.4 请求与错误捕获

| ID | 需求 | 优先级 |
| --- | --- | --- |
| FR-30 | 记录请求/响应全量信息：method、URL、headers、body、status、耗时、发起方（页面/堆栈） | P0 |
| FR-31 | 错误聚合：4xx/5xx、网络错误、超时、CORS 失败、console error、未捕获异常（含堆栈） | P0 |
| FR-32 | 按时间线展示，支持筛选（仅错误 / 仅命中规则 / 关键字） | P1 |
| FR-33 | 请求详情一键加入诊断上下文；**点选某条请求即诊断该条**（不回放）；导出 HAR | P1 |

### 3.7 AI 诊断

| ID | 需求 | 优先级 |
| --- | --- | --- |
| FR-60 | 对话式诊断：用户描述问题，系统自动打包上下文（请求/错误/日志/源码）；DEMO 基于 Claude Agent SDK 实现 | P0（DEMO 已验证） |
| FR-61 | 工具化检索：模型通过 **MCP（进程内）** 调用只读工具读取日志与源码 | P1 |
| FR-62 | 结构化输出 DiagnosisResult：元数据 + target + 请求/响应 + marker 披露 + 时间窗统计 + agent 段（结论原文 + 证据链[工具参数 + 返回原文]） | P0（DEMO 已验证） |
| FR-63 | 多轮追问、上下文增删、结论一键复制/导出 | P1 |
| FR-64 | 历史会话沉淀与相似问题检索 | P2 |
| FR-65 | 硬闸门 + n=3 多次判定：记录一致/不一致/判不了，界面声明“一致不等于正确”（细则见 06 T11） | P1 |
| FR-66 | 诊断轮次上限 24 轮；产出 DiagnosisResult 与脱敏报告 | P0（DEMO 已验证） |
| FR-67 | 脱敏报告采用**白名单投影**后渲染：保留目标名/症状/耗时/结论/请求/摘要/工具计数/自检；去除绝对路径、头值、日志与源码原文 | P0（DEMO 已验证） |

### 3.8 安全与隐私

| ID | 需求 | 优先级 |
| --- | --- | --- |
| FR-70 | 发送给模型前的内容预览与手动剔除 | P1 |
| FR-71 | 默认脱敏规则：Authorization/Cookie/Set-Cookie/常见 token 字段 | P1 |
| FR-72 | 仅本地模型模式（离线） | P2 |
| FR-73 | 运行进程识别：列出本机进程的 pid/ppid/name/startedAt/脱敏 command，默认当前用户/会话，支持 pid/port/name/commandContains/javaOnly 过滤；command 先脱敏再截断 | P1 |
| FR-74 | 诊断前 Triage：开始诊断前收集复现环境/影响范围/最近变更 2–3 个判别性问题，答案作为用户先验注入证据包顶部和报告开头；可跳过，CLI 支持 `--triage` / `--triage-file` | P1 |
| FR-75 | 只读文件/Git 工具：`list_dir` / `stat_file` 返回目录与文件元数据；`git_status` / `git_log` / `git_diff` 只读查看仓库状态与近期变更；默认隐藏敏感路径，Git 默认 stat，完整 patch 需显式单文件路径 | P1 |
| FR-76 | 工具边界可发现：边界错误返回 `hint/usage/details`；同一工具同类边界错误连续 2 次追加 `guardrail`，提示停止试探；system prompt 提供紧凑工具边界表 | P1 |
| FR-77 | Maven 结果复用：`run_command` 对重复的 Maven 查询和成功 compile 做 per-run 缓存（≤5 分钟，写入后清空，返回 `cached/cacheAgeMs`）；新增 `maven_dependencies` 原子工具，一次全量 tree、内部过滤 includes/excludes，并可生成 `declaredFile` 供 `runtime_classpath` 使用 | P1 |
| FR-78 | 用量诊断：usage 保留 per-model provider/canonicalModel/costBasis/cache 明细与逐轮摘要；UI/报告展示缓存读/写、模型/供应商与成本（非官方 provider 标“估算”）；systemPrompt 使用 static prefix + dynamic boundary 提升跨会话缓存命中 | P1 |
| FR-79 | 自动修复重试：sandbox / in-place / full 验证失败时，将结构化失败输出回灌给模型并自动重试一次；受剩余轮次/费用/时间约束；仍失败才落回原 needsMoreInfo 行为；readonly 与 recheck>1 不重试 | P1 |
| FR-98 | 症状验证：编译/测试通过不等于症状消失；结果提供显式「症状验证」待办（已消失/仍存在/无法验证），整体状态分为 verified/unverified/failed（编译未执行但症状已确认时单列 symptom-verified），待确认不得显示绿色 | P0 |
| FR-99 | 安全重放：仅对配置启用、允许 origin、默认 GET/HEAD、无认证头的捕获请求生成 fixture 并自动重放；比较 HTTP/业务错误签名更新症状状态；不可重放时回退人工确认 | P1 |
| FR-100 | 非代码修复动作：`actions` 与代码 `fixes` 平级，支持 config/build/dependency/runtime/data/deployment/environment，包含前置条件、步骤、可复制命令、验证方式、风险与可逆性；P0 只展示不自动执行 | P0 |
| FR-101 | 长列表分页：列表工具发生截断时全量溢写到 evidence，返回 total/offset/limit/nextOffset/file/fields；`query_result` 支持 field/offset/limit/filter 二次查询；`runtime_classpath` 支持 mode/offset/limit；`maven_dependencies` 支持 offset/limit | P0 |
| FR-102 | 构建/IDE 模型探针：可配置只读探针根（默认源码根父目录）；`inspect_build_model` 返回 Maven POM 模块/父坐标、IntelliJ modules.xml/iml、源目录与时间戳，并给出模型过期证据；不读同级源码或 workspace.xml | P0 |
| FR-103 | 参数化运行时事实：`runtime_facts` 按 pid/port + view + selectors 读取 system_properties/classloader/flags/command_line；支持 comparePid/declaredFile 只返回差异；敏感值脱敏、通配只返回键名、结果分页/溢写 | P0 |
| FR-104 | 源码/配置检索扩展：`search_source` 默认纳入 POM/YAML/properties/JSON 等配置，支持 includeConfig/caseSensitive、安全正则（worker + 5s 超时）、offset/limit/nextOffset 稳定分页与 query_result 续页；`read_source` 可按路径直接读取配置；排除锁文件/压缩产物/source map 与敏感文件，越界路径和不允许的类型明确拒绝 | P0 |
| FR-105 | 结论可证伪：输出必填 `rejectedHypotheses`（被排除的备选假设 + 至少 1 条真实证据引用 + 理由）；确实无可排除假设时允许空数组但必须给 `noRejectedHypothesesReason`；gate 校验假设结构、理由与引用是否真实存在于证据包，recheck 比较多次运行的排除假设是否一致 | P0 |
| FR-106 | 验证语义清理：删除模型自填且从不执行的每条修复 `verification` 字段；实际验证只来自编译/测试自检与工作区验证命令；模型自评置信度在报告/UI/CLI 明确标注“未校准，仅供参考” | P0 |
| FR-107 | 写盘路径策略统一：agent Edit/Write 与补丁预览/应用/撤销共用 `core/write-policy.mjs`，统一校验可写根、realpath/符号链接、敏感文件、`.git`/`node_modules`、Git 忽略的构建产物；已跟踪的 build/out 仍允许，补丁落盘前再复查一次 | P0 |
| FR-108 | 项目级诊断记忆：按源码/前端仓库根 hash 保存本地诊断笔记（日志格式、环境差异、已排除假设），下次诊断作为「工具积累的项目前提」单独注入，与用户本次 Triage 分开标注来源；自动沉淀日志格式与合规的已排除假设，支持 UI 增删改/置顶、`--no-memory`、报告/CLI 审计与追问快照 | P0 |
| FR-109 | 验证分层：构建自检与测试自检分开报告；自动探测后端测试（Maven/Gradle/Go/Python）并默认执行，前端 test 脚本只提示；测试失败默认 warning、不阻断/隐藏修复，配置 `required` 后才阻断；支持有序 `verifyCommands`（build/test、root、required）和 `verifyRunTests` 开关，报告/CLI/UI/gate 明示本次是否运行测试 | P0 |
