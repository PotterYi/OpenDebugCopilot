# 02 功能需求

## 3. 功能需求

优先级：**P0** = MVP 必须；**P1** = 首个可用版本；**P2** = 增强。

### 3.1 工作区管理（Workspace）

| ID | 需求 | 优先级 |
| --- | --- | --- |
| FR-01 | 新建/编辑/删除工作区；保存前端地址端口、后端地址端口、日志路径（支持多个文件/目录）、源码根目录 | P0 |
| FR-02 | 连通性与路径校验（端口是否可达、路径是否存在、日志是否可读） | P0 |
| FR-03 | 多工作区切换、配置导入导出（JSON） | P1 |
| FR-04 | 可选：启动命令/环境变量、后端进程关联（用于后续进程级诊断） | P2 |

### 3.2 内嵌浏览器

| ID | 需求 | 优先级 |
| --- | --- | --- |
| FR-10 | 内嵌浏览器加载本地/远端页面，支持多标签、前进后退、刷新 | P0 |
| FR-11 | 内置 DevTools 开关；自定义 UA、窗口尺寸、缓存清理 | P1 |
| FR-12 | 支持自签名证书/HTTPS 提示与信任策略 | P1 |
| FR-13 | 页面注入标识（如 trace header / 页面角标），提示“当前已接管” | P1 |

### 3.3 路由控制 / 流量规则（核心能力）

| ID | 需求 | 优先级 |
| --- | --- | --- |
| FR-20 | 规则匹配：HTTP 方法、URL（通配符/正则）、资源类型（xhr/fetch/document/ws）、Origin/Referer、Header 条件 | P0 |
| FR-21 | 规则动作：转发到指定上游（本地后端）、直接响应（Mock）、中断（Abort）、延迟、改写路径、增删改 Header、改写 Request/Response Body | P0（转发/中断）/ P1（Mock、改包、延迟） |
| FR-22 | 规则优先级、启停、启用状态可视化、命中次数与最近命中时间 | P0 |
| FR-23 | 规则命中日志与可回放（查看该请求的最终去向） | P1 |
| FR-24 | 规则导入导出、按工作区隔离 | P1 |
| FR-25 | WebSocket / SSE 透传与规则支持 | P2 |

### 3.4 请求与错误捕获

| ID | 需求 | 优先级 |
| --- | --- | --- |
| FR-30 | 记录请求/响应全量信息：method、URL、headers、body、status、耗时、发起方（页面/堆栈） | P0 |
| FR-31 | 错误聚合：4xx/5xx、网络错误、超时、CORS 失败、console error、未捕获异常（含堆栈） | P0 |
| FR-32 | 按时间线展示，支持筛选（仅错误 / 仅命中规则 / 关键字） | P1 |
| FR-33 | 请求详情一键加入诊断上下文；**点选某条请求即诊断该条**（不回放）；导出 HAR | P1 |

### 3.5 日志采集

| ID | 需求 | 优先级 |
| --- | --- | --- |
| FR-40 | 本地日志文件增量 tail（断点续读），日志轮转（rotation）检测 | P0 |
| FR-41 | 多行堆栈合并、时间戳解析、级别识别；内置常见格式模板（logback/log4j、JSON、Node、Python） | P0（基础）/ P1（模板） |
| FR-42 | 按时间窗 + 关键字 / traceId 检索，结果高亮 | P0 |
| FR-43 | 日志与请求的关联（traceId 注入与提取、时间窗兜底） | P1 |
| FR-44 | 自定义解析模板（正则具名分组） | P2 |

### 3.6 源码上下文

| ID | 需求 | 优先级 |
| --- | --- | --- |
| FR-50 | 文件树浏览 + 全文搜索（ripgrep 语义） | P1 |
| FR-51 | 堆栈帧 → file:line 映射并跳转（Java/Node/Python/Go 启发式） | P1 |
| FR-52 | 符号大纲（tree-sitter）与路由 → Controller/Handler 映射 | P2 |
| FR-53 | git 信息读取（最近改动、blame）作为诊断线索 | P2 |

### 3.7 AI 诊断

| ID | 需求 | 优先级 |
| --- | --- | --- |
| FR-60 | 对话式诊断：用户描述问题，系统自动打包上下文（请求/错误/日志/源码）；DEMO 基于 Claude Agent SDK 实现 | P0（DEMO 已验证） |
| FR-61 | 工具化检索：模型通过 **MCP（进程内）** 调用只读工具读取日志与源码 | P1 |
| FR-62 | 结构化输出 DiagnosisResult：元数据 + target + 请求/响应 + marker 披露 + 时间窗统计 + agent 段（结论原文 + 证据链[工具参数 + 返回原文]） | P0（DEMO 已验证） |
| FR-63 | 多轮追问、上下文增删、结论一键复制/导出 | P1 |
| FR-64 | 历史会话沉淀与相似问题检索 | P2 |
| FR-65 | 硬闸门 + n=3 多次判定：记录一致/不一致/判不了，界面声明“一致不等于正确”（细则见 06 T11） | P1 |
| FR-66 | 诊断轮次上限 24 轮；产出 DiagnosisResult 与脱敏报告 | P0（DEMO 已验证） |
| FR-67 | 脱敏报告采用**白名单投影**后渲染：保留目标名/症状/耗时/结论/请求/摘要/工具计数/自检；去除绝对路径、头值、日志与源码原文 | P0（DEMO 已验证） |

### 3.10 运行形态（已确认，见 08）

| ID | 需求 | 优先级 |
| --- | --- | --- |
| FR-90 | 同一套诊断编排支持三种入口：CLI、本地 WebUI、Electron 桌面版 | P0（DEMO 已验证） |
| FR-91 | 不设独立守护进程：WebUI 的服务即 CLI 进程；桌面版由主进程托管同一 HTTP 服务，随窗口生灭 | P0（DEMO 已验证） |
| FR-92 | 桌面版使用 WebContentsView 承载真实 Chromium，CDP 捕获请求 | P0（DEMO 已验证） |
| FR-93 | 路由方案：webRequest 三钩子按前缀改道（`onBeforeRequest` 改路由 / `onBeforeSendHeaders` 抓预检头 / `onHeadersReceived` 补 CORS）；**自建壳 + dev server 代理已淘汰，不实现** | P0（钩子已验证） |
| FR-94 | 场景文件 browser 块：path + match（URL 子串）+ actions[]（仅 click / fill，playwright 选择器，不支持 select）；有 browser 块走浏览器驱动，有 method/path 走 HTTP 驱动，歧义直接报错 | P0（DEMO 已验证） |
| FR-95 | 证据工具 5 个：get_logs、list_threads、search_log、read_source、search_source；工具结果溢出落盘，由内置 read 取回 | P0（DEMO 已验证） |
| FR-96 | 日志关联 marker：注入 `dcprobe<随机hex>` 到可被日志回显、不参与业务的 body 字段，agent 用 get_logs({marker}) 子串匹配；无安全字段则不注入并在 prompt 明说 | P0（DEMO 已验证） |
| FR-97 | 日志落盘等待：固定 sleep 1.2s（实测链路延迟约 150ms）；慢系统截断风险待评估（T18） | P0（DEMO 已验证） |
