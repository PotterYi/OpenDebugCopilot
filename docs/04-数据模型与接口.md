## 5. 数据模型

### 5.1 已确认（DEMO）：无数据库，文件化

| 数据 | 位置 | 说明 |
| --- | --- | --- |
| 配置 | `configs/*.json` | 工作区/默认参数等 |
| 多工作区配置 | `configs/profiles.json` | `{activeId, profiles:[{id,name,workspace,routing,...}]}`；切换时写回 workspace/routing |
| 场景 | `scenarios/*.json` | path + match + actions / method + path / logfiles / source / parser / marker / window |
| 数据库连接 | `configs/databases.json` | `{activeId, connections:[{id,name,host,port,user,database,allowWrite,...}]}`；密码用 Electron safeStorage 加密或引用环境变量 |
| 诊断历史 | `runs/<runId>/` | 每次运行一个目录；含 `result.json`、`report.md`、`evidence/`、`db-queries/` |
| UI 状态 | 浏览器 `localStorage` | 仅界面态，不作为事实来源 |
| Claude 认证 | `configs/agent-auth.json` + `~/.claude/settings.json` | 应用凭据优先：`mode=user` 读用户设置；`custom` 使用 safeStorage 加密 Token；`env` 读取指定环境变量。IPC 只返回 `hasToken`，绝不回传 Token |

- **不引入数据库**：查询能力由文件扫描提供；需要历史检索时再评估索引方案。
- `runs/` 建议保留策略：按 runId 目录独立，可整目录删除或归档；具体保留天数【待确认 T19】。

### 5.2 运行目录结构（M1 已实现）

```
runs/<runId>/
  result.json      # DiagnosisResult（六段）
  meta.json        # 场景、驱动、耗时、预检结果、工作区模式提示
  evidence/        # 工具结果溢出文件（tool-NNN-<name>.json）
  db-queries/      # query_db / write_db 的完整查询结果（dbq-NNN-<ts>.json）
  baseline/        # Git 原地模式的逐文件版本快照；保留/丢弃后清理
  sandbox/         # 非 Git 诊断的隔离副本
  sandbox-followup-<ts>/  # 继续诊断的独立隔离副本（每次唯一）
  workspace-journal.json  # 原地模式会话状态（未收尾恢复）
  report.md        # 白名单投影后的脱敏报告
```

- 目录由 `--runs-dir` 指定，默认仓库根 `runs/`；每次运行独立目录。
- 工具结果超过 32KB 自动溢写到 `evidence/`，由内置 `read` 工具取回。
- 每次数据库查询都写入 `db-queries/`，`result.json` 只保留连接、SQL、行数等元数据；
  **删除诊断目录时查询结果随之删除**，不存在跨运行缓存。
- Git 原地模式的 `result.json` 内含 `agent.workspaceSession`（pending/kept/discarded），
  首次写入前内容快照位于 `baseline/`；未决状态下工作区锁保持，禁止删除该诊断。
  `workspaceSession.changedFiles` 列出本轮所有实际写入的文件（含跳过/二进制/冲突），
  `workspaceSession.touchedFiles` 附带 `file/relative/root/preHash/lastHash/存在性`，
  以及 `versions/currentVersion`（pre-run 为 v0，每次写入后追加一个版本）。
- 每次写入前/后、自测完成、保留/丢弃都会原子更新 `workspace-journal.json`；
  应用启动扫描 `status=editing|pending` 的 journal 并提示恢复，已 `kept|discarded`
  的 journal 不允许重放，避免误回滚用户已保留的修改。
- `meta.workspaceNotice` 记录本次工作区模式与原因：`in-place`、`copy`（非 Git 隔离副本）、
  `readonly`（抢锁失败 / 副本超限 / 基线失败）；`busy` 时附带占用诊断的
  `runId/pid/at`，UI 据此展示只读原因与「锁释放后重试」入口。
- 继续诊断每次使用唯一的 `sandbox-followup-<ts>/` 目录，结束后清理；同一 run
  同时只允许一个继续诊断，避免共享沙箱目录触发 Windows 文件锁（EBUSY）。
- `baseline/` 只保存实际写入文件的快照，不再拷贝全部脏文件；每个文件保留
  pre-run（v0）及每次写入后的版本快照。保留/丢弃成功或 journal 恢复完成后删除，
  存在冲突时保留以便重试。
- 结果页可对单个文件选择版本回退（`dc:workspace` action `restore-file`）；
  外部修改冲突时拒绝回退。应用重启后可从 `workspace-journal.json` 执行同样的回退。
- 只读模式只做静态检查；隔离副本在沙箱内运行编译/测试，真实源码树只在原地 /
  完全权限模式下被修改。
- 写入真实工作区后的校验结果位于 `agent.verification`
  （`scope/mode/status/commands/error/reason/output/durationMs`）；
  `meta.verificationStatus` 同步用于历史列表「验证失败」徽标。失败时
  `gates.checks` 增加 `compile-self-check` 并使 `gates.ok=false`，报告与 CLI 同步展示。

## 6. 接口设计

### 6.1 M1（CLI）

| 入口 | 说明 |
| --- | --- |
| `node src/app/cli.mjs run <scenario> [--check] [--mock] [--recheck N]` | 执行一次诊断，产物写入 `runs/<runId>/` |
| `node src/app/cli.mjs serve [--port N]` | 启动共享 WebUI（静态页 + `/api/*`） |
| 退出码 | 0 成功；非 0 用于场景错误、预检失败、诊断失败 |

### 6.2 模块间接口（M1 约定）

| 边界 | 约定 |
| --- | --- |
| `driver → capture` | `fire()` 返回统一 `{ request, response, firedAt, marker }` |
| `evidence → tools` | 三个日志查询 + 两个源码查询，均为同步/异步普通函数 |
| `tools → agent` | 工具名 snake_case + JSON Schema；返回 JSON 可序列化结果 |
| `diagnose → report` | 输入 DiagnosisResult，输出白名单投影后的结构化对象 |

### 6.3 WebUI HTTP API（M2-S1 已实现）

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/health` | 健康检查 |
| GET/PUT | `/api/config` | 工作区 + 路由规则 |
| GET/PUT | `/api/databases` | 数据库连接配置（密码脱敏） |
| POST | `/api/databases/test` | 测试单个数据库连接 |
| GET | `/api/runs` | 诊断历史 |
| GET | `/api/runs/:runId` | result.json + report.md |
| DELETE | `/api/runs/:runId` | 删除诊断及其 `db-queries/` 查询结果 |
| GET | `/*` | 静态页面（`src/ui`） |

详细契约与桌面 IPC 映射见 11 §11.3 / §11.4。

### 6.4 桌面 / WebUI 阶段（后置，设计草案）

| 通道 | 方向 | 说明 |

| `workspace:list/save/delete/validate` | RPC | 工作区管理 |
