## 5. 数据模型

### 5.1 已确认（DEMO）：无数据库，文件化

| 数据 | 位置 | 说明 |
| --- | --- | --- |
| 配置 | `configs/*.json` | 工作区/默认参数等 |
| 多工作区配置 | `configs/profiles.json` | `{activeId, profiles:[{id,name,workspace,routing,...}]}`；切换时写回 workspace/routing |
| 场景 | `scenarios/*.json` | path + match + actions / method + path / logfiles / source / parser / marker / window |
| 数据库连接 | `configs/databases.json` | `{activeId, connections:[{id,name,host,port,user,database,allowWrite,...}]}`；密码用 Electron safeStorage 加密或引用环境变量 |
| 诊断历史 | `runs/<runId>/` | 每次运行一个目录；含 `result.json`、`report.md`、`evidence/`、`db-queries/` |
| UI 状态 | 浏览器 `localStorage` | 仅界面态，不作为事实来源 |
| Claude 认证 | `configs/agent-auth.json` + `~/.claude/settings.json` | 应用凭据优先：`mode=user` 读用户设置；`custom` 使用 safeStorage 加密 Token；`env` 读取指定环境变量。IPC 只返回 `hasToken`，绝不回传 Token |

- **不引入数据库**：查询能力由文件扫描提供；需要历史检索时再评估索引方案。
- `runs/` 建议保留策略：按 runId 目录独立，可整目录删除或归档；具体保留天数【待确认 T19】。

### 5.2 运行目录结构（M1 已实现）

```
runs/<runId>/
  result.json      # DiagnosisResult（六段）
  meta.json        # 场景、驱动、耗时、预检结果、工作区模式提示
  evidence/        # 工具结果溢出文件（tool-NNN-<name>.json）
  db-queries/      # query_db / write_db 的完整查询结果（dbq-NNN-<ts>.json）
  baseline/        # Git 原地模式的逐文件版本快照；保留/丢弃后清理
  sandbox/         # 非 Git 诊断的隔离副本
  sandbox-followup-<ts>/  # 继续诊断的独立隔离副本（每次唯一）
  workspace-journal.json  # 原地模式会话状态（未收尾恢复）
  report.md        # 白名单投影后的脱敏报告
```

项目级诊断记忆不在 run 目录内，而是按仓库根 hash 存在 `configs/diagnosis-memory.json`；删除某个 run 不会删除项目笔记，用户可在 UI 手动删除。

- 目录由 `--runs-dir` 指定，默认仓库根 `runs/`；每次运行独立目录。
- 工具结果超过 32KB 自动溢写到 `evidence/`，由内置 `read` 工具取回。
- 每次数据库查询都写入 `db-queries/`，`result.json` 只保留连接、SQL、行数等元数据；
  **删除诊断目录时查询结果随之删除**，不存在跨运行缓存。
- Git 原地模式的 `result.json` 内含 `agent.workspaceSession`（pending/kept/discarded），
  首次写入前内容快照位于 `baseline/`；未决状态下工作区锁保持，禁止删除该诊断。
  `workspaceSession.changedFiles` 列出本轮所有实际写入的文件（含跳过/二进制/冲突），
  `workspaceSession.touchedFiles` 附带 `file/relative/root/preHash/lastHash/存在性`，
  以及 `versions/currentVersion`（pre-run 为 v0，每次写入后追加一个版本）。
- 每次写入前/后、自测完成、保留/丢弃都会原子更新 `workspace-journal.json`；
  应用启动扫描 `status=editing|pending` 的 journal 并提示恢复，已 `kept|discarded`
  的 journal 不允许重放，避免误回滚用户已保留的修改。
- `meta.workspaceNotice` 记录本次工作区模式与原因：`in-place`、`copy`（非 Git 隔离副本）、
  `readonly`（抢锁失败 / 副本超限 / 基线失败）；`busy` 时附带占用诊断的
  `runId/pid/at`，UI 据此展示只读原因与「锁释放后重试」入口。
- 继续诊断每次使用唯一的 `sandbox-followup-<ts>/` 目录，结束后清理；同一 run
  同时只允许一个继续诊断，避免共享沙箱目录触发 Windows 文件锁（EBUSY）。
- `baseline/` 只保存实际写入文件的快照，不再拷贝全部脏文件；每个文件保留
  pre-run（v0）及每次写入后的版本快照。保留/丢弃成功或 journal 恢复完成后删除，
  存在冲突时保留以便重试。
- 结果页可对单个文件选择版本回退（`dc:workspace` action `restore-file`）；
  外部修改冲突时拒绝回退。应用重启后可从 `workspace-journal.json` 执行同样的回退。
- 只读模式只做静态检查；隔离副本在沙箱内运行编译/测试，真实源码树只在原地 /
  完全权限模式下被修改。
- 写入真实工作区后的校验结果位于 `agent.verification`
  （`scope/mode/status/commands/error/reason/output/durationMs`）；
  `meta.verificationStatus` 同步用于历史列表「验证失败」徽标。失败时
  `gates.checks` 增加 `compile-self-check` 并使 `gates.ok=false`，报告与 CLI 同步展示。

## 6. 接口设计

### 6.1 M1（CLI）

| 入口 | 说明 |
| --- | --- |
| `node src/app/cli.mjs run <scenario> [--check] [--mock] [--recheck N] [--no-memory]` | 执行一次诊断，产物写入 `runs/<runId>/`；默认注入并沉淀项目记忆 |
| `node src/app/cli.mjs serve [--port N]` | 启动共享 WebUI（静态页 + `/api/*`） |
| 退出码 | 0 成功；非 0 用于场景错误、预检失败、诊断失败 |

### 6.2 模块间接口（M1 约定）

| 边界 | 约定 |
| --- | --- |
| `driver → capture` | `fire()` 返回统一 `{ request, response, firedAt, marker }` |
| `evidence → tools` | 三个日志查询 + 两个源码查询，均为同步/异步普通函数 |
| `diagnose → agent (triage)` | `result.meta.triage` 保存 `{asked, skipped, answers, labels, note, askedAt}`；`evidence.triage` 注入证据包顶部，报告在结论前展示「诊断前提」 |
| `evidence → tools (process)` | `list_processes` 返回 `pid/ppid/name/startedAt/脱敏 command`；默认当前用户/会话，支持 pid/port/name/commandContains/javaOnly 与 limit |
| `evidence → tools (fs/git)` | `list_dir` / `stat_file` 返回相对路径、类型、大小、mtime；`git_status` / `git_log` / `git_diff` 返回只读 Git 元数据，默认隐藏敏感路径并限制输出 |
| `tools (maven)` | `maven_dependencies` 解析全量 dependency:tree 并在内部过滤，返回依赖列表与可选 `declaredFile`；`run_command` 对可复用 Maven 命令返回 `cached/cacheAgeMs` |
| `agent → result (usage)` | `agent.usage` 包含聚合 token、`models[]`（provider/canonicalModel/costBasis/cache 明细）、`perTurn[]` 与 `costEstimated`；报告/UI 据此显示缓存与成本来源 |
| `diagnose → repair` | 验证失败时构造结构化 `failure`，调用 `agent.followUp({ purpose:'repair', failure, budget })`；`verification.repair` 与 `agent.repair` 记录 attempted/finalStatus/skippedReason/budget/usage |
| `result.symptomCheck` | `{status, method:'manual'|'replay'|'element-recheck', steps, expected, observed, note, reason, signature, evidence, checkedAt, markedAt}`；元素复检证据含 before/after 截图路径与 JSON；gates.level = verified/symptom-verified/unverified/failed |
| `result.logs.correlation` | `{strategy,matchedId,strength,caveat,businessIds,traceId}`；marker/trace=strong、business/window-thread=medium、time-window=weak、none=none；进入 Agent 证据包、报告/UI/CLI 与追问快照 |
| `result.agent.actions` | 非代码修复动作数组；含 type/summary/requires/steps/commands/verification/risk/reversible/execution；P1 支持 execution.status（pending/confirmed/passed/failed/skipped/not-applicable）与 command 白名单验证结果；`meta.actionStatus`/`gates.actions` 汇总 |
| `result.agent.fixes` | 代码修复只含 summary/root/file/search/replace/content/risk/note；不含模型自填 verification。真实执行结果在 `fix.applied.verification`，全局自检在 `agent.verification` |
| `result.agent.confidence` | 模型自评 0..1；报告/UI/CLI 明确标注“未校准，仅供参考”，不作为正确性背书 |
| `result.meta.memory` | `{enabled,projectKey,projectName,noteCount,used[],candidatesSaved,saveError?}`；used 保存本次实际注入的笔记快照，供报告/CLI/UI 审计与追问复用 |
| `diagnosis-memory` | `configs/diagnosis-memory.json`（本地、gitignore）：`{version,projects:{m-<hash>:{name,roots,notes[]}}}`；按源码/前端根 hash 分组，不跟 profile 绑定 |
| `core/write-policy` | `checkWritablePath({target,roots,root?,relative?})` 统一校验可写根、realpath、敏感文件、`.git`/`node_modules` 与 Git 忽略的构建产物；agent 与补丁预览/应用/撤销共用 |
| `workspace.verifyCommands` / `verifyRunTests` | 有序验证命令：`[{command,phase:'build'|'test',root?,extraRoot?,required?}]`；`verifyCommand` 作为单条覆盖；`verifyRunTests=false` 关闭自动探测到的测试 |
| `agent.verification` | 保留阻断用 `status`；新增 `buildStatus/testStatus/buildCommands/testCommands/testRequired/testBlocking/testError/testReason/testHints/testsAvailable`；只有失败且 required 的测试才 `testBlocking=true` 并改变 `status` |
| `agent.repair` / `workspace.agent.repairRetry` | `repairRetry` 支持 enabled/maxAttempts/maxTurns/maxBudgetUsd/timeoutMs；repair 结果含 attempts/maxAttempts/failure(最后一轮)/history(最近 3 次摘要)/budget/finalStatus/skippedReason；总预算和总超时覆盖整个循环 |
| gates build/test | `compile-self-check` 对应构建（skipped 为 warn）；`test-self-check` 对应测试，失败默认 warn，`required:true` 时 error |
| `verification.suspicions` / `testSummary` | 成功命令输出命中强信号（BUILD FAILURE、测试失败计数、0 用例、离线跳过等）时返回 `{phase,code,message,line}`；`testSummary` 记录 tests/failures/errors；gate `output-suspicion` 为 warn，不改变 status |
| `core/verify-output` | 流式扫描全部输出 chunk，剥离 ANSI、截断单行、最多 5 条疑点；退出码/超时仍是硬判据，裸 `ERROR` 不触发 |
| `tools` 结果上限 | `MAX_TOOL_RESULT_BYTES=20KB`（`core/tool-limits.mjs`）；`safe()`/SDK 包装层自动 `ensureSpill`，返回 `{spilled,file,bytes,preview}`；无指针时不再静默截断，返回 `TOOL_RESULT_UNSPILLED` |
| `evidence/tool-NNN-*.json` | 所有超过 20KB 的工具结果均落盘；`read` 按行读取，`query_result` 按 field/offset/limit 分页 |
| `result.agent.rejectedHypotheses` | `[{hypothesis, refutedBy:[{type,ref,note?}], reason}]`；最多 5 条，refutedBy 至少 1 条且 ref 必须存在于证据包；空数组需 `noRejectedHypothesesReason` |
| `evidence refs` | `core/evidence-refs.mjs` 从证据包构建路径索引（request/response/logs.records[i]/source.files[i]/threads/element 等）；gate 对支持结论与否定证据统一校验存在性 |
| `query_result` / list envelope | `{file,totalCount,offset,limit,nextOffset,truncated,capped,droppedCount,fields,items}`；`MAX_TOTAL_ITEMS=20000` 且 offset 上限一致；超过上限先截断并显式 `capped/droppedCount`，不再返回不可达 nextOffset；`query_result` 读取 evidence JSON 并按 field/offset/limit/filter 取页 |
| `search_source` | 输入 `{keyword,regex?,caseSensitive?,includeConfig?,root?,extraRoot?,offset,limit}`；返回 `{matches[],totalCount,offset,limit,nextOffset,hasMore,truncated,capped,scannedFiles,scannedBytes,fields}`；配置默认包含，正则走 worker |
| `read_source` | 输入 `{target,root?,extraRoot?,startLine?,endLine?}`；target 可为类名、源码路径或配置路径；返回 `{found,relativePath,startLine,endLine,totalLines,content,truncated}` 或候选/拒绝原因 |
| `inspect_build_model` | 输入 `{root:'backend'|'frontend'}`；返回 `{buildSystem,poms[],gradle,frontend,ide,staleHints[],limitations[]}`；Gradle/frontend 走静态文件，`buildProbeRoots` 分别配置探针根 |
| `runtime_facts` | 输入 `{pid|port,view:'system_properties'|'classloader'|'flags'|'command_line'|'environment',selectors[],comparePid?,declaredFile?,offset,limit}`；environment 仅 Linux，其他平台返回 unsupported limitation；环境变量同样应用 deny/脱敏 |
| `result.replayFixture` | 安全捕获请求 fixture（method/url/安全头/body/origin）；不含 Authorization/Cookie/token。`replay.allowCredentials=true` 时敏感头仅内存传入 replay，fixture 只记录 `credentials:'session'` |
| `dc:runs element-recheck` | 桌面端打开原页面、重渲染同一 selector，返回/保存 before-after 截图与 `evidence/element-recheck.json`；状态为 failed（缺失/完全未变）或 pending（有变化待确认） |
| `evidence → tools (JVM)` | `list_java_processes` 列出本地 Java 进程；`runtime_classpath` 采集运行侧 classpath，与声明清单在工具内部求差集，只返回差异与计数 |
| `tools → agent` | 工具名 snake_case + JSON Schema；返回 JSON 可序列化结果；边界错误额外返回 `details / hint / usage`，连续第 2 次同类错误追加 `guardrail` |
| `diagnose → report` | 输入 DiagnosisResult，输出白名单投影后的结构化对象 |

### 6.3 WebUI HTTP API（M2-S1 已实现）

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/health` | 健康检查 |
| GET/PUT | `/api/config` | 工作区 + 路由规则 |
| GET/PUT | `/api/databases` | 数据库连接配置（密码脱敏） |
| POST | `/api/databases/test` | 测试单个数据库连接 |
| GET | `/api/runs` | 诊断历史 |
| GET | `/api/runs/:runId` | result.json + report.md |
| DELETE | `/api/runs/:runId` | 删除诊断及其 `db-queries/` 查询结果；存在未收尾工作区修改时返回 409，需 `?keep=1` 先保留后删除 |
| GET | `/*` | 静态页面（`src/ui`） |

详细契约与桌面 IPC 映射见 11 §11.3 / §11.4。
