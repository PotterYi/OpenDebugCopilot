## 11.1 目标与范围

**目标**：在 M1 CLI 内核之上，交付 Electron 桌面版，并让同一套页面可被本地 WebUI 复用。

```
Electron 主进程
├─ UI HTTP 服务（静态页面 + /api/*，与 WebUI 共用）
├─ 诊断内核（复用 src/core、driver、evidence、tools、agent、diagnose、report）
├─ BrowserHost：WebContentsView + CDP 捕获
├─ Router：session.webRequest 三钩子 + 规则
└─ preload → 5 个 dc:* IPC

渲染页面（零框架 HTML+JS）：工作区 / 请求时间线 / 诊断 / 报告
内嵌页面（WebContentsView）：用户实际调试的前端页面
```

**包含**

| 能力 | 说明 |
| --- | --- |
| 本地 UI 服务 | Node http server；`serve` 命令；桌面与 WebUI 共用 |
| Electron 壳 | Electron 45；加载同一页面；`contextIsolation` + preload |
| 内嵌浏览器 | WebContentsView（真实 Chromium），导航/刷新/DevTools |
| 捕获 | CDP Network 事件 + 响应体；内存环形缓冲 |
| 路由 | `onBeforeRequest` 改道、`onBeforeSendHeaders` 预检、`onHeadersReceived` 补 CORS |
| 点选诊断 | **不回放**；以捕获到的请求/响应为诊断对象 |
| 5 个 IPC | config / browser / capture / diagnose / runs |
| 持久化 | `configs/*.json` + `runs/<runId>/` |

**配置目录**：桌面/真实使用写入项目 `configs/`；`manual:e2e` 使用 `.tmp/manual-e2e/configs` 作为**测试临时配置**，关闭后清理，UI 会明确标注。测试临时目录统一由 `verify/unit/tmp.mjs` 计算。

**工作区字段**：后端地址、日志文件、后端源码目录、前端源码目录；前端地址不再单独填写，由浏览器地址栏维护（打开页面时自动写回配置），避免重复输入。

**不包含（后续）**

- 安装包/自动更新（M2-S6 只做可运行，不追求签名发布）
- 多窗口、多标签浏览器、团队规则共享
- 非浏览器客户端流量
- 规则脚本化（mock/改包），M2 只做"前缀改道"

## 11.3 5 个 `dc:*` IPC（提案）

| 通道 | 方向 | 职责 | 主要载荷 |
| --- | --- | --- | --- |
| `dc:config` | invoke | 读取/保存工作区与路由规则 | `{ action: 'get' \| 'save', config }` |
| `dc:browser` | invoke | 导航、刷新、前进后退、DevTools、视图 bounds | `{ action, url? }` |
| `dc:capture` | invoke + event | 请求列表、详情、清空；新请求事件推送 | `{ action: 'list' \| 'get' \| 'clear' }` |
| `dc:diagnose` | invoke + event | 以某条捕获请求发起诊断；进度事件 | `{ requestId, question, recheck? }` |
| `dc:runs` | invoke | 诊断历史与报告读取 | `{ action: 'list' \| 'get', runId }` |

- preload 只暴露白名单：`window.dc.invoke(channel, payload)` 与 `window.dc.on(event, handler)`。
- 渲染页不直接接触 Node API；`contextIsolation: true`、`nodeIntegration: false`。
- **T20 待确认**：如果 DEMO 里的 5 个通道已有既定名称/参数，以实际为准。

## 11.4 HTTP API（WebUI 与桌面共用契约）

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET/PUT | `/api/config` | 工作区与路由规则 |
| GET | `/api/captures` | 捕获列表（支持 `type=xhr,fetch`、`errorsOnly`） |
| GET | `/api/captures/:id` | 单条请求/响应详情 |
| POST | `/api/captures/clear` | 清空 |
| POST | `/api/diagnose` | `{ requestId, question, recheck? }` → `{ runId }` |
| GET | `/api/runs` | 历史列表 |
| GET | `/api/runs/:runId` | result.json + report.md |
| GET | `/api/health` | 健康检查 |
| GET | `/*` | 静态页面（零框架） |

桌面版不复用 HTTP API 调用，而是用 5 个 IPC；但两端由同一个 **服务层** 实现，避免两份逻辑。

> **端口必须固定（默认 7080）**：桌面与 WebUI 使用同一 origin。`localStorage` 按 origin 隔离，
> 随机端口会导致历史配置永远读不到且不报错；端口被占用时直接报错，不静默换端口。

## 11.5 内嵌浏览器与捕获

- 窗口结构：`BrowserWindow` 承载应用 UI；`WebContentsView` 作为子视图叠加在右侧内容区。
- 内嵌浏览器使用独立会话 `persist:dc-browser`，路由钩子只作用于该会话，不影响应用 UI 自身请求。
- **本机地址统一用 `localhost`**：`127.0.0.1` 在嵌入视图里会触发 `ERR_ABORTED`，
  打开页面与路由目标都会自动归一化。
- 布局：左侧面板固定 380px，顶部工具栏 48px；主进程在 `resize` 时调用 `setBounds`。
**配置与路由可观测性**：工作区页显示配置文件目录；保存后在消息中回显路径。路由页显示「已加载 N 条规则」、
命中次数与最近一次未命中的 URL；规则保存后立即生效。左右分栏可拖动，宽度存 `localStorage`（固定 origin）。

**零框架 UI 约定**：用 `hidden` 属性控制显隐时，全局样式保留 `[hidden] { display: none !important; }`；
组件的 `display` 规则会覆盖 UA 的 `[hidden]`，导致 `el.hidden = true` 静默失败。冒烟测试会检查
`diagnose-result` 的 `hidden` 属性与 `computedStyle.display === 'none'` 一致。

> **导航就绪判据**：`loadURL()` 的 resolve 只代表导航开始，不代表落地（实测那一刻 `getURL()` 可能仍是上一页）；
> 一律用 `webContents.isLoading()`。UI 打开页面后轮询 `dc:browser` 的 `status`，直到 `isLoading=false` 才更新地址栏与状态。

- CDP：`webContents.debugger.attach('1.3')`，**在首个 `dom-ready` 后再 `Network.enable`**
  （WebContentsView 在首次导航前没有 renderer target，过早调用会挂起 CDP 会话）；监听：
  - `Network.requestWillBeSent`（URL、方法、headers、postData、时间、类型）
  - `Network.responseReceived`（状态、headers、MIME）
  - `Network.loadingFinished`（耗时；按需 `Network.getResponseBody` 取体，默认上限 1MB）
  - `Network.loadingFailed`（错误原因）
- 存储：内存环形缓冲（默认 500 条）+ 详情按需拉取；`dc:capture` 事件用于 UI 增量渲染。
- 过滤：默认可只看 `xhr/fetch`；文档/图片等可切换显示。

## 11.6 路由：三钩子与 CORS

规则文件 `configs/routing.json`（提案）：

```json
{
  "rules": [
    {
      "id": "local-order",
      "enabled": true,
      "match": { "host": "api.example.com", "prefix": "/api/order" },
      "target": { "kind": "local", "baseUrl": "http://127.0.0.1:8080" }
    },
    {
      "id": "sit-user",
      "enabled": true,
      "match": { "host": "api.example.com", "prefix": "/api/user" },
      "target": { "kind": "sit", "baseUrl": "https://sit.example.com" }
    }
  ]
}
```

| 钩子 | 行为 |
| --- | --- |
| `onBeforeRequest` | 按 host + prefix 匹配规则；命中则 `redirectURL = target.baseUrl + path + query`；记录命中规则 |
| `onBeforeSendHeaders` | 对改道到本地的请求，记录预检携带的 `Access-Control-Request-*` 头；按需补齐 `Origin/Referer` |
| `onHeadersReceived` | 对本机目标响应补 CORS：`Access-Control-Allow-Origin`（页面 origin）、`Allow-Credentials`、`Allow-Headers`、`Allow-Methods`、`Expose-Headers` |

**风险与兜底**：

1. **OPTIONS 不重定向**：Chromium 会拒绝预检重定向，因此预检仍发往原地址，只由 `onHeadersReceived` 补 CORS 头。
   若本地后端完全不处理 `OPTIONS`（返回 404/405），预检仍会失败；后续可评估本地反向代理方案。
2. `webRequest` 只能改 URL/头，**拿不到 body**；请求/响应体一律由 CDP 侧提供。
3. CDP 看到的 URL 是改道前还是改道后，需要在 S4 用真实日志确认；诊断证据以 CDP 的最终 URL 为准。
4. Cookie 域：改道后 `Set-Cookie` 的 Domain 可能与本地后端不一致，M2 只做最小处理，必要时在报告标注。

### 11.6.1 CORS 四坑与预检缓存

| 坑 | 处理 |
| --- | --- |
| 入口 HTML 也会被挡 | 路由默认只对 `resourceType=xhr` 生效；document / script / stylesheet 不改道 |
| 预检不经过原 origin 的钩子 | 预检不重定向；按规则匹配补 CORS；无法覆盖时发出 `cors-warning`，不静默 |
| 通配符带凭据不算通配 | **仅 local 目标**回显请求实际 Origin（可能是字符串 `null`），仅此时加 `Allow-Credentials`；无 Origin 才用 `*` 且不加凭据。SIT 不改头 |
| 预检必须返回 2xx | **仅 local 目标**：内置代理直接返回 204；直连 local 时在 `onHeadersReceived` 把非 2xx 的 `statusLine` 改写为 `HTTP/1.1 200 OK` 并记录 repaired。SIT 原样透传，不掩盖网关 4xx |
| 预检缓存导致假绿 | 响应加 `Access-Control-Max-Age: 0`；保存规则时 `clearCache()`，避免旧预检结果掩盖问题 |
| JSON POST 触发预检 | 改道后跨域，`Content-Type: application/json` 会触发 OPTIONS；手工 E2E 的 stub 前后端都已实现 OPTIONS 204，真实后端也必须这样 |
| 改道后的 URL | **默认直接把请求改道到目标地址**（浏览器里就是 `http://localhost:8080/xxx`），不再暴露代理 URL；`DC_ROUTING_PROXY=1` 可启用内置代理兜底（CORS/预检/认证更稳，但 URL 会显示 `/__dcproxy`） |
| 跨域认证头 | 浏览器跨源重定向会剥离 Authorization；按 CDP 捕获的**完整原始 URL** 请求头在目标请求上恢复 |

### 11.6.2 路由辅助（三源合并）

候选规则必须同时满足三个来源，缺一不出规则：

| 来源 | 内容 |
| --- | --- |
| 观测 | 当前捕获的 XHR/Fetch，按 host + 前两段路径分组 |
| 声明 | 工作区 `backendUrl` + 现有规则里的 `target`（local/SIT） |
| 探测 | 对候选地址实际探活，只有可达的地址才会被选中 |

- 选择顺序：已声明的 local 优先，local 不可达才尝试已声明的 SIT；全部不可达则该组前缀剔除并提示。
- 规则编辑器带表头（启用 / Host / 前缀 / 类型 / 目标地址 / 探测 / 状态 / 操作）。
- **目标地址是下拉选择，不是自由输入**：选项按类型限定为探测可达的候选。
  - 本地候选：工作区 `backendUrl`、已有 local 规则、`扫描本机端口` 发现的可达端口
  - SIT 候选：工作区 `sitUrl`、已有 SIT 规则、捕获请求中出现过的**非 loopback** origin
  - loopback（localhost/127.0.0.1）地址必须显式声明，不从抓包推断；旧代理 URL（`/__dcproxy`）会被忽略
  - 切换类型会重新过滤；候选为空时显示“未探测到可用地址”，可点「刷新候选」
  - 「扫描本机端口」：探测常见端口并把可达端口加入本地候选；「刷新候选」：重新探活当前所有候选并刷新下拉
- 类型「本地」= 改道到本机并补 CORS/预检；类型「SIT」= 转发到测试环境，网关 CORS/状态原样透传。
- 逐条可切换 local/SIT；“探测”按钮可手动复查；自动生成的规则显示“可达（自动）”。
- 前缀已被**具体规则**覆盖时不重复生成；`prefix: "/"` 的兜底规则不阻止更具体候选。
- SIT 目标指向本机时给出警示（本地 SIT 靶场合法，但需用户确认）。
- 纯函数在 `src/ui/routing-assist.mjs`（异步，注入 probe），单测覆盖三源、不可达、去重与 catch-all 场景。

## 11.7 点选诊断（不回放）

> M2-S5 已实现：`runCaptureDiagnosis(observation, { workspace, ... })` 复用共享的
> `diagnoseWithFired`；不 fire、不注入 marker；日志关联走三层（marker → 时间窗+线程 → 业务 ID）。
> UI 默认 Mock 诊断，真实模型需显式点击；结果写入同一套 `runs/<runId>/`。

M1 的 `runDiagnosis(scenario)` 会**主动发起请求**，桌面版不能用它（点选请求不应重放）。需要把编排拆成两段：

```
collectEvidence(observation, config)  // 捕获到的请求/响应 + 日志 + 线程 + 源码
diagnoseAndPersist(evidence, agent, options)
```

- `runDiagnosis(scenario)` = driver.fire → collectEvidence → diagnoseAndPersist（M1 行为不变）。
- `runCaptureDiagnosis(observation, config)` = 直接用 CDP 捕获的数据 → diagnoseAndPersist；**不 fire、不注入 marker**。
- marker 缺失时，日志关联退回时间窗；结果中标注 `marker.injected=false` 与关联方式。

捕获对象（observation）拟：

```js
{
  request: { method, url, headers, body, startedAt },
  response: { status, statusText, ok, headers, body, durationMs, error },
  firedAt,           // 请求开始时间
  resourceType,      // xhr | fetch | document ...
  ruleId             // 命中的路由规则（可空）
}
```

## 11.7.1 前端错误与源码接入

- 内嵌页启用 CDP `Runtime` 域，捕获 `Runtime.exceptionThrown` 与 error/assert 级 `consoleAPICalled`（最多保留 200 条）。
- UI 请求页显示页面错误数量；诊断时把最近 20 条前端错误纳入证据包。
- 使用 `frontendSourceRoot` 解析前端堆栈帧（URL → 源码路径，失败时按 basename 回退），最多 3 处源码片段。
- 请求/响应体若是 JSON（按 Content-Type 或 `{`/`[` 形态判断），展示前自动 `JSON.stringify(…, null, 2)` 美化；非 JSON、截断或超大内容保持原文。
- 请求页左侧新增「页面错误」列表：每条错误都有「诊断」按钮，以 CONSOLE 伪请求 + 错误堆栈为证据走同一套编排。
- 请求诊断只保留一个「诊断此请求」按钮（真实模型）；Mock 仅保留给 CLI/自动化测试，不再出现在 UI。
- 现象描述改为独立整行 textarea，不再挤在按钮工具栏里。
- 报告摘要增加“前端错误 / 前端源码片段”计数；提示词同步携带 `frontend` 证据。

## 11.7.2 捕获响应体修复

- 原实现用自增 id 存记录、却用 CDP `requestId` 查响应/响应体，导致状态与响应体永远缺失；已改为 `requestId` 索引。
- XHR / Fetch / Document 响应体自动抓取（最多重试 3 次，≤1MB）；失败记录原因，UI 提供“重新获取”。
- 详情页始终展示“响应体”区块（成功/失败/不可用原因），不再静默隐藏。

## 11.7.3 运行日志与排查

| 日志 | 位置 | 内容 |
| --- | --- | --- |
| 全局日志 | 开发：项目 `logs/debugcopilot.log`；打包：优先安装目录 `logs/`（可写时），否则 `userData/logs/`（另写 stderr） | 启动、配置加载/保存、路由命中/未命中、预检兜底、代理启动、浏览器 console/请求失败、IPC 异常 |
| 单次诊断日志 | `runs/<runId>/run.log` | 场景/问题、日志关联策略与条数、agent、gates、复核判定、耗时、产物路径 |
| 轮转 | 单个文件 5MB × 保留 3 份 | 防止无限增长 |

- **桌面「日志」页签**：日志文件直接使用工作区 `logfiles`（不再重复输入/选文件），选择解析器（auto / pipe / spring-boot / logback / json-lines / node / 自定义正则），以选中的捕获请求为锚点按时间窗查询并展示。
- 自动探测失败时不再硬猜：UI 提示改用具体解析器；新增 **pipe（竖线分隔）** 预设。
- 轮转文件按 **修改时间** 升序扫描，结果按日志时间排序，避免先读到旧文件。
- `DC_LOG_FILE` 可覆盖日志文件；`DC_DEBUG=1` 打开 debug 级（如非 XHR 的路由未命中）。
- 工作区页只显示日志文件路径；桌面版的「打开日志文件 / 在文件夹中显示」放在应用菜单栏「日志」下（File / Edit / View / Window 旁边）。
- 排查顺序：按时间戳/URL 找 `[routing]`/`[routing miss]`/`[cors-warning]` → 对应 `runs/<runId>/run.log` 看诊断链路。
- stdout 仍只输出主结果，日志不会污染 stdout。

## 11.10 验证方式

1. **单元测试**：配置原子写、规则匹配、捕获归一化、HTTP API handler、报告渲染。
2. **WebUI 验证**：`serve` 启动，用 `fetch` 直接打 `/api/*`；页面能完成一次 Mock 诊断。
3. **桌面冒烟**：启动 Electron 加载页面后自动退出（`--smoke` 参数）；检查 5 个 IPC 白名单可用。
4. **手工 E2E**：stub 前端（按钮触发 `/api/order`）+ stub 后端（500）+ 日志 → 内嵌页 → 路由改道 → 点选诊断（Mock，不花钱）→ 报告。
5. **真实模型**：只在需要时手动跑一次（沿用 `--budget-usd` 上限）。
6. **输入测试限制**：CDP / 合成事件绕过浏览器命中测试，**不能验证原生 WebContentsView 是否截走点击**；
   视图边界、覆盖关系、真实点击必须用**真实鼠标**手工验收。
7. **判据禁忌**：避免“什么都没变”式断言（请求失败也会静默通过）；使用正向断言（捕获数、响应码、runId、gates.ok、报告出现）。
8. **UI 就绪判据**：`did-finish-load` 不代表模块脚本初始化完成；冒烟轮询 `window.__dcUIReady` 并读取 `__dcUIError`，防止“页面已加载但 UI 未初始化”的假绿。
9. **跨源判据**：涉及 CORS/改道的验收必须使用**绝对地址的跨源请求**（页面 A 域请求 B 域）；同源形状会假绿，测不出 Origin 回显与预检。
10. **stdout 纪律**：stdout 只放主结果（JSON/结论/启动 URL/冒烟结果）；日志走 stderr 或文件，禁止污染 stdout（判分逻辑会拼接输出切结论）。
11. **生成页面脚本的转义**：不要把换行写进单引号字符串（本次手工 harness 因 `'
'` 落成真实换行导致脚本语法错误、点击无反应）。内嵌页 console 错误统一写 stderr（`[browser console]`）。
12. **测试必须执行代码**：禁止源码文本断言；harness 页面抽到 `verify/manual/page.mjs`，单元测试用假 DOM + 假 fetch **实际触发 click 处理器**，Electron 冒烟用同一份页面真实执行点击与请求。

## 11.11 风险

| 风险 | 应对 |
| --- | --- |
| 预检/OPTIONS 本地后端不支持 | 先按三钩子实现；失败则启用 `/api/preflight-echo` 兜底 |
| CDP 与 webRequest 的 URL 口径不一致 | S4 用日志与时间线对齐；证据以 CDP 为准 |
| Electron WebContentsView 布局/DPI | 固定布局 + resize 重算；先只保证 Windows |
| 捕获 body 的内存占用 | 环形缓冲 + 单条 1MB 上限 + 详情按需加载 |
| 5 个 IPC 与 DEMO 命名不一致 | T20 确认后再定；先按提案实现，改名成本低 |
| 桌面测试自动化成本 | 以单测 + 冒烟 + 手工 E2E 为主，不追求全 UI 自动化 |
| Electron 参数陷阱 | 裸 URL 作为位置参数会导致 Electron 启动异常；内部参数统一用 `--flag=value` 形式 |
| 预检失败 | local 规则已由内置反向代理兜底；SIT 目标仍要求自身支持 OPTIONS |
| 端口漂移 | UI 端口固定 7080；占用时报错，不随机换端口（避免 localStorage 与历史错乱） |
| 预检失败静默 | local 规则由内置代理应答；直连/SIT 非 2xx 改写状态行为 200 并记录 repaired 事件 |
| 自动化假绿 | 合成输入无法验证原生视图拦截；覆盖/边界用手工真实鼠标验收 |
| 打包依赖下载 | electron-builder 的 winCodeSign/NSIS 常走 GitHub；当前网络不稳定，打包评估列为 T24 |
